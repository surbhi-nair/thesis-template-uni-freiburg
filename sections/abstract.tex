\section*{Abstract}

Converting relational data into an RDF knowledge graph (KG) is straightforward with a direct mapping, but the result mirrors how the data is stored rather than what it describes. Turning it into a semantically modeled KG, with domain entities, meaningful classes and predicates, and explicit relationships, still requires a knowledge engineer to understand the domain and the schema and to write the mapping by hand.

In this thesis, we investigate to what extent an LLM agent can automate this step by generating SPARQL CONSTRUCT queries that transform a generic KG, obtained by a direct mapping, into a semantic KG\@. We extend the agent framework GRASP with a generation agent that explores the generic KG through a SPARQL endpoint, designs the model, and tests each query on the data, and an independent review agent that checks the submitted queries against the data, supported by a mechanically computed source coverage. The queries depend only on the schema, so they can be inspected, corrected, and executed on the complete data.

We compare our approach with a general-purpose coding agent, OpenCode, which receives the same generic KG as a file and uses the same LLM\@. We evaluate both on eight datasets: IMDb, Mondial, and MusicBrainz, with 7 to 239 tables, and five databases of the BIRD benchmark, which we model with and without competency questions. We evaluate the output on three levels: whether the queries execute on QLever, an LLM judge that scores the model against nine criteria, and a manual analysis with analytical SPARQL queries.

All query sets of our approach execute without changes, while six of the twelve query sets of the baseline required interventions, although the baseline reported them as tested. Without competency questions, our approach scores at least as high as the baseline on all seven datasets where both produced a result, with a mean of 8.5 against 7.6 out of 10 on the BIRD databases, and far fewer major issues. On IMDb, its graph is also simpler and faster to query on every analytical question. Competency questions improve the baseline, but slightly lower the scores of our approach, which narrows its model towards the questions. On MusicBrainz, the largest schema, the score drops to 6.7, with errors in the naming and direction of relationships and in date encoding that a user cannot detect from query results.
